# Features

> Honest inventory of what this project does, by status. Generated by studying
> the actual code, not the marketing claims. Updated as features ship, change,
> or break. Citations point at symbols (not line numbers — those rot).

## Status legend

Every label answers ONE question: does working code exist — and if not, why
not?

| Status                    | Meaning                                                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🟢 `FULLY_FUNCTIONAL`     | Works as intended, exercised by tests or daily use.                                                                                                     |
| 🟡 `PARTIALLY_FUNCTIONAL` | Ships but has known gaps, edge-case bugs, or missing pieces.                                                                                            |
| 🔴 `BROKEN`               | Present in code but failing. Keep BROKEN nameable — "zero BROKEN rows" is itself information.                                                           |
| 🔵 `DISABLED`             | Code exists and is correct, but execution is externally switched off (flag, missing credentials, CI off). A switch, not a fix — never fold into BROKEN. |
| ⚪ `PLANNED`              | No code yet; genuinely next on the build path.                                                                                                          |

> The v0.1 honesty contract (README): everything that talks to the LIVE stack
> is implemented but untested against real infrastructure until a device train
> against the operator's stack. What IS testable without it — the protocol
> layer (RFC vectors), the push router (Robolectric shadows), the build/packa-
> ging lane — has been upgraded to `FULLY_FUNCTIONAL` with its evidence. First
> emulator smoke (install + launch + render) passed 2026-10-24; that proves
> the app boots, not that a call works.
